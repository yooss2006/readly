# Readly 구현 핸드오프

이 문서의 초기 목표와 완료 기준은 첫 MVP 구현 전에 작성한 기록이다. 현재 제품 정책은 [기획 기록](./ADR.md), 구현 선택은 [기술 결정 기록](./TECHNICAL_DECISIONS.md)을 기준으로 한다. 설치와 실행 절차는 [README](../README.md)를 따른다.

## 현재 구현 상태 (2026-09-23)

- Next.js·TypeScript 웹 앱에 Google 로그인, 초대 이메일 제한, URL별 공유 요약·음성, 일일 생성 횟수와 월 비용 제한을 구현했다.
- 일반 사용자의 재생성 요청과 대기 표시, 방장 `yoofh2006@gmail.com`의 홈 요청 목록·건수 표시·단건·일괄·즉시 재생성 경로를 구현했다. 동일 글의 요청은 한 건으로 모으며, 재생성 성공 시 요청과 이전 음성을 해제한다.
- 방장의 일회용 초대장 발급·내역·사용 전 취소와 받은 사람의 편지 화면·Google 로그인 수락 경로를 추가했다. 초대장 토큰은 7일 뒤 만료되고 성공한 신규 등록 한 번에만 소비된다. 운영 DB 적용과 OAuth 설정 상태는 아래 확인 사항을 따른다.
- 이번 변경에서 `npm run typecheck`와 `npm run build`가 통과했다. 브라우저에서 데스크톱·모바일 초대장 화면의 WebGL 렌더링과 편지 열기 동작을 확인했다. 로컬 PostgreSQL 바이너리가 없어 `npm test`의 DB 통합 테스트는 건너뛰었고, 별도 PostgreSQL 호환 로컬 실행에서 초대장 SQL의 권한·1회 사용·취소·만료를 확인했다. 실제 PostgreSQL의 동시 수락 경쟁과 Google OAuth 연결은 아직 확인하지 못했다.
- [재생성 마이그레이션](../supabase/migrations/202609230002_regeneration.sql)을 추가했다. 로컬 PostgreSQL 테스트에서 권한, 중복 요청, 실패 시 기존 결과 보존, 성공 시 요청·음성 해제를 확인했다. `npm run typecheck`와 `npm run build`도 통과했다.
- `readly` Supabase 프로젝트에서 방장 계정과 `allowed_emails` 등록을 확인하고 초대장 마이그레이션을 적용했다(원격 등록명 `20260923093520_invitations`). `invitation_links`의 RLS가 켜져 있고 정책은 0개이며, 초대장 함수는 `service_role`만 실행할 수 있다. 운영 PostgreSQL 트랜잭션에서 방장 발급, 미등록 방장 거절, 기존 회원의 링크 미소비, 취소·만료 후 사용 거절을 확인하고 롤백했다. 초대장 테스트 행은 남지 않았다.
- 사용자가 배포 도메인을 `https://readly-omega.vercel.app/`로 알려주었다. 운영 Supabase Auth의 Site URL과 두 Redirect URL은 [README](../README.md#시작하기)에 적었다. 설정 적용 여부와 실제 Vercel 응답은 아직 확인하지 못했다.
- 원격의 기존 테이블과 재생성 관련 테이블은 확인했으나, 기존 마이그레이션 적용 이력과 실제 Google OAuth, 새 계정의 수락 및 동시 수락 경쟁, 외부 서비스 스모크 테스트, Vercel 배포 상태는 확인하지 않았다.

## 초기 구현 목표 (작성 당시)

- 초대한 사용자만 이용할 수 있는 URL 글 요약 웹 서비스를 구현한다.
- 사용자는 요약만 생성하거나 요약과 음성을 함께 생성할 수 있다.
- 같은 URL의 저장된 결과를 재사용하고, 기존 요약에 음성만 추가할 수 있다.
- 계정별 일일 생성 제한과 서비스 전체 월 비용 제한을 적용한다.
- 실제 동작과 중요한 경계 조건을 검증하는 테스트를 포함한다.

## 초기 확정 범위 (작성 당시)

- 대상은 로그인 없이 열리는 정보성 글이다.
- 첫 MVP는 일반 웹 글만 받으며 PDF URL은 받지 않는다.
- 요약과 음성은 한국어로 제공한다.
- 사용자는 Google 계정으로 로그인하며, 허용된 이메일만 접근한다.
- 새 요약 생성, 요약과 음성 동시 생성, 기존 요약에 음성 추가는 계정별 하루 최대 5회 중 각각 1회로 센다. 저장된 결과 조회는 횟수에 포함하지 않는다.
- 성공한 생성만 일일 횟수에서 차감한다. 요약은 성공했지만 음성이 실패하면 요약을 보관하고, 음성은 나중에 재시도할 수 있다.
- 요약과 음성을 함께 요청했을 때 요약만 성공하면 1회 차감한다. 나중에 음성 추가에 성공하면 1회를 더 차감한다.
- 같은 URL의 요약과 음성은 사용자들이 함께 이용한다. 기존 요약이 있으면 그대로 반환한다.
- 새 요청에 따른 본문 추출·요약·음성 생성 비용의 월 상한은 3만 원이다. 앱은 예상 비용 2만 4천 원에 도달하면 새 생성을 멈추고, 저장된 결과 조회는 허용한다.
- 실패한 요청이라도 외부 서비스에서 실제로 청구한 비용은 월 비용 계산에 포함한다.
- 본문 추출은 Firecrawl 무료 구간에서 시작한다. 무료 사용량이 소진되면 새 본문 추출을 중단한다.

## 초기 확정 기술 방향 (작성 당시)

- Next.js와 TypeScript로 웹 화면과 서버 처리를 한 프로젝트에 구현한다.
- 인증, 요약 데이터, 음성 파일 보관은 Supabase Free를 사용한다.
- 웹 앱 배포 대상은 Vercel Hobby다.
- 요약과 음성 생성은 OpenAI를 사용한다. 현재 선택한 모델은 [기술 결정 기록](./TECHNICAL_DECISIONS.md#초기-mvp-구현-선택-2026-09-23)에 남겼다.
- OpenAI 전용 프로젝트에 강제 월 지출 상한과 사전 알림을 설정한다.
- 첫 MVP는 실제 Vercel 배포까지 완료한다.

## 요약 작성 기준

사용자는 요약 형식을 정할 때 `technical-writing` 스킬을 참고하도록 요청했다. 기본 출력은 `핵심 요지`의 짧은 개요와 `주요 내용`의 항목 목록으로 구성한다. 항목 수를 맞추기보다 독자가 본문을 읽기 전에 알아야 할 내용을 훑기 쉽게 정리한다. 원문의 수치, 조건, 부정, 인과관계, 주장 주체를 유지하고 원문에 없는 사실을 보태지 않는다. 결과에는 원문을 확인할 수 있는 링크를 제공한다.

이 기준을 구현 세션에서 요약 프롬프트와 실제 글을 사용한 품질 점검에 적용한다. 요약 길이와 항목 수는 글의 내용에 맞춰 조절한다.

## 비밀값과 버전 관리

- 로컬 API 키와 다른 비밀값은 `.env`에서 관리한다. `.env`는 Git에 추적되지 않아야 한다.
- 사용자는 새 세션 전에 필요한 외부 서비스 계정과 API 키를 준비할 수 있다고 답했다. 키 값은 채팅이나 문서에 적지 않는다.
- `.gitignore`는 `.env`와 그 변형 파일을 제외하고, 값이 없는 `.env.example`은 추적한다.
- 비밀값은 브라우저 코드, 로그, 테스트 출력에 노출하지 않는다. 배포 환경의 비밀값은 배포 서비스의 환경 변수로 설정한다.
- 현재 작업 공간에는 구현 소스와 Git 저장소가 있다. 로컬 `.env`는 Git 추적 대상이 아니다.

## 초기 테스트 완료 기준 (작성 당시)

- 테스트는 로그인 접근 제한, 동일 URL 재사용, 요약만 생성, 요약과 음성 생성, 기존 요약에 음성 추가, 일일 제한, 월 비용 제한, 외부 서비스 실패를 검증한다.
- 동시에 들어온 요청이 같은 URL의 중복 생성이나 일일·월 제한 초과를 일으키지 않는지도 검증한다.
- 부분 성공을 검증한다. 요약 성공 후 음성이 실패하면 요약을 다시 만들지 않고 보관된 요약에 음성을 추가할 수 있어야 한다.
- 테스트를 통과시키기 위해 구현과 같은 답만 돌려주는 무의미한 Mock 테스트를 만들지 않는다. 순수 규칙은 실제 입력과 기대 결과로 검증하고, 저장·인증 연동은 가능한 범위에서 실제 테스트 환경으로 검증한다.
- 준비된 API 키로 Firecrawl과 OpenAI의 실제 호출을 확인하는 스모크 테스트를 실행한다. 결과가 원문의 핵심을 보존하는지 사람이 확인한다. 외부 계정 접근이 실제로 막히면 해당 검증을 실행하지 못한 이유를 명시한다.
- 허용된 Google 계정과 허용되지 않은 계정의 접근 결과를 확인한다.
- `.env`가 Git 추적 대상에서 제외되는지 확인한다.
- 배포된 Vercel URL에서 로그인, 요약, 음성, 저장된 결과 재조회가 실제로 작동하는지 확인한다.

## 현재 확인 필요 사항

- 운영 DB에는 초기·재생성 관련 테이블이 있으나 해당 마이그레이션의 기록은 조회되지 않았다. 저장소 파일명 `202609230003_invitations.sql`과 원격 적용 이력 `20260923093520_invitations`의 버전도 다르다. 향후 Supabase CLI로 마이그레이션을 밀기 전에 이력과 실제 스키마를 대조한다.
- Supabase Auth Redirect URLs에 `https://readly-omega.vercel.app/auth/invite-callback`과 기존 로그인용 `https://readly-omega.vercel.app/auth/callback`을 등록하거나 이미 허용되는지 확인한다. Supabase 연결 도구에 Auth URL 설정 조회·변경 기능이 없어 이 항목은 미완료다. 실제 Google 계정으로 초대장 1회 사용·취소, 일반 사용자 권한, 편지 화면을 확인한다.
- 허용·비허용 Google 계정으로 로그인 제한을 확인한다. 일반 사용자 요청, 방장 단건·일괄·즉시 재생성, 다른 계정에서 갱신된 공유 요약 확인, 기존 음성 해제를 실제 브라우저에서 검증한다.
- Firecrawl·OpenAI 스모크 테스트와 요약 품질 확인을 현재 환경에서 다시 수행할지 결정한다. Vercel 배포 상태와 배포된 앱의 핵심 동작, OpenAI 강제 지출 상한·알림 설정도 확인한다.
