# Readly 초기 MVP 구현 핸드오프

이 문서는 새 세션에서 Readly의 초기 MVP와 의미 있는 테스트를 한 번에 구현하기 위한 출발점이다. 제품 결정은 [ADR.md](./ADR.md), 기술 결정은 [TECHNICAL_DECISIONS.md](./TECHNICAL_DECISIONS.md)를 기준으로 한다. `구현 세션에서 정할 사항`은 아직 확정된 세부 기술 선택이 아니다.

## 구현 목표

- 초대한 사용자만 이용할 수 있는 URL 글 요약 웹 서비스를 구현한다.
- 사용자는 요약만 생성하거나 요약과 음성을 함께 생성할 수 있다.
- 같은 URL의 저장된 결과를 재사용하고, 기존 요약에 음성만 추가할 수 있다.
- 계정별 일일 생성 제한과 서비스 전체 월 비용 제한을 적용한다.
- 실제 동작과 중요한 경계 조건을 검증하는 테스트를 포함한다.

## 확정된 범위

- 대상은 로그인 없이 열리는 정보성 글이다.
- 첫 MVP는 일반 웹 글만 받으며 PDF URL은 받지 않는다.
- 요약과 음성은 한국어로 제공한다.
- 사용자는 Google 계정으로 로그인하며, 허용된 이메일만 접근한다.
- 새 요약 생성, 요약과 음성 동시 생성, 기존 요약에 음성 추가는 계정별 하루 최대 5회 중 각각 1회로 센다. 저장된 결과 조회는 횟수에 포함하지 않는다.
- 성공한 생성만 일일 횟수에서 차감한다. 요약은 성공했지만 음성이 실패하면 요약을 보관하고, 음성은 나중에 재시도할 수 있다.
- 요약과 음성을 함께 요청했을 때 요약만 성공하면 1회 차감한다. 나중에 음성 추가에 성공하면 1회를 더 차감한다.
- 같은 URL의 요약과 음성은 사용자들이 함께 이용한다. 기존 요약이 있으면 그대로 반환한다.
- 새 요청에 따른 본문 추출·요약·음성 생성 비용의 월 상한은 3만 원이다. 앱은 예상 비용 2만 4천 원에 도달하면 새 생성을 멈추고, 저장된 결과 조회는 허용한다.
- 실패한 요청이라도 외부 서비스에서 실제로 청구한 비용은 월 비용 계산에 포함한다.
- 본문 추출은 Firecrawl 무료 구간에서 시작한다. 무료 사용량이 소진되면 새 본문 추출을 중단한다.

## 확정된 기술 방향

- Next.js와 TypeScript로 웹 화면과 서버 처리를 한 프로젝트에 구현한다.
- 인증, 요약 데이터, 음성 파일 보관은 Supabase Free를 사용한다.
- 웹 앱 배포 대상은 Vercel Hobby다.
- 요약과 음성 생성은 OpenAI를 사용한다. 구체적인 모델은 아직 정하지 않았다.
- OpenAI 전용 프로젝트에 강제 월 지출 상한과 사전 알림을 설정한다.
- 첫 MVP는 실제 Vercel 배포까지 완료한다.

## 요약 작성 기준

사용자는 요약 형식을 정할 때 `technical-writing` 스킬을 참고하도록 요청했다. 기본 출력은 `핵심 요지`의 짧은 개요와 `주요 내용`의 항목 목록으로 구성한다. 항목 수를 맞추기보다 독자가 본문을 읽기 전에 알아야 할 내용을 훑기 쉽게 정리한다. 원문의 수치, 조건, 부정, 인과관계, 주장 주체를 유지하고 원문에 없는 사실을 보태지 않는다. 결과에는 원문을 확인할 수 있는 링크를 제공한다.

이 기준을 구현 세션에서 요약 프롬프트와 실제 글을 사용한 품질 점검에 적용한다. 요약 길이와 항목 수는 글의 내용에 맞춰 조절한다.

## 비밀값과 버전 관리

- 로컬 API 키와 다른 비밀값은 `.env`에서 관리한다. `.env`는 Git에 추적되지 않아야 한다.
- 사용자는 새 세션 전에 필요한 외부 서비스 계정과 API 키를 준비할 수 있다고 답했다. 키 값은 채팅이나 문서에 적지 않는다.
- 구현 시 `.gitignore`에 `.env`와 그 변형 파일을 포함하고, 값이 없는 `.env.example`을 제공한다.
- 비밀값은 브라우저 코드, 로그, 테스트 출력에 노출하지 않는다. 배포 환경의 비밀값은 배포 서비스의 환경 변수로 설정한다.
- 현재 작업 공간에는 구현 소스가 없고, `.git`, `.gitignore`, `.env` 파일도 없다. 새 세션에서 실제 상태를 다시 확인한다.

## 테스트 완료 기준

- 테스트는 로그인 접근 제한, 동일 URL 재사용, 요약만 생성, 요약과 음성 생성, 기존 요약에 음성 추가, 일일 제한, 월 비용 제한, 외부 서비스 실패를 검증한다.
- 동시에 들어온 요청이 같은 URL의 중복 생성이나 일일·월 제한 초과를 일으키지 않는지도 검증한다.
- 부분 성공을 검증한다. 요약 성공 후 음성이 실패하면 요약을 다시 만들지 않고 보관된 요약에 음성을 추가할 수 있어야 한다.
- 테스트를 통과시키기 위해 구현과 같은 답만 돌려주는 무의미한 Mock 테스트를 만들지 않는다. 순수 규칙은 실제 입력과 기대 결과로 검증하고, 저장·인증 연동은 가능한 범위에서 실제 테스트 환경으로 검증한다.
- 준비된 API 키로 Firecrawl과 OpenAI의 실제 호출을 확인하는 스모크 테스트를 실행한다. 결과가 원문의 핵심을 보존하는지 사람이 확인한다. 외부 계정 접근이 실제로 막히면 해당 검증을 실행하지 못한 이유를 명시한다.
- 허용된 Google 계정과 허용되지 않은 계정의 접근 결과를 확인한다.
- `.env`가 Git 추적 대상에서 제외되는지 확인한다.
- 배포된 Vercel URL에서 로그인, 요약, 음성, 저장된 결과 재조회가 실제로 작동하는지 확인한다.

## 구현 세션에서 정할 사항

- OpenAI의 구체적인 요약·음성 모델과 음성을 실제 글 및 비용 기준으로 선택하고 [기술 결정 기록](./TECHNICAL_DECISIONS.md)에 남긴다.
- Next.js 프로젝트 내부의 폴더 구조와 모듈 경계는 구현자가 정한다. 외부 서비스 비밀값은 서버에서만 사용하고, URL별 재사용과 사용량·비용 제한이 동시 요청에서도 유지되도록 한다.
- 현재 Git 저장소가 없으므로 구현 세션에서 버전 관리와 Vercel 배포 경로를 정한다. 어떤 경로를 선택하든 `.env`가 추적되지 않는지 검증한다.
