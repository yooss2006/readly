# Readly 기술 결정 기록

## 확정된 방향

- 기술 선택에서는 MVP의 빠른 완성을 우선하고, 최적화는 MVP 완성 후 진행한다.
- 요약 생성과 요약본 음성 생성은 외부 서비스를 이용해 시작한다.
- 요약 생성과 요약본 음성 생성은 처음에 한 업체의 서비스를 이용한다.
- 그 업체는 OpenAI로 시작한다.
- URL의 본문 추출은 외부 서비스를 이용해 시작한다. 차후 비용이 발생하면 앱에서 직접 추출하는 방향으로 전환한다.
- 본문 추출은 Firecrawl 무료 구간에서 시작한다.
- Firecrawl 무료 사용량이 소진되면 유료 전환 없이 새 본문 추출을 중단한다.
- 웹 화면과 서버 처리는 한 프로젝트로 시작한다.
- 웹 앱 프레임워크는 Next.js를 사용한다.
- 웹 앱 코드는 TypeScript로 작성한다.
- 앱 배포와 요약·음성 결과 보관에는 관리형 서비스를 이용한다.
- 계정 인증, 요약 데이터, 음성 파일 보관에는 Supabase Free를 이용한다.
- 웹 앱 배포에는 Vercel Hobby를 이용한다.
- 첫 MVP 구현의 완료 범위에는 실제 Vercel 배포가 포함된다.
- 로그인은 Google 계정으로 하고, 허용한 이메일만 접근할 수 있게 한다.
- 앱은 새 생성 요청의 예상 비용을 합산해 월 2만 4천 원에 도달하면 새 생성을 중단한다. 보관된 결과 조회는 계속 허용한다.
- OpenAI 전용 프로젝트에 월 2만 4천 원보다 낮은 금액에 해당하는 강제 지출 상한과 사전 지출 알림을 설정한다.

## 초기 MVP 구현 선택 (2026-09-23)

- 요약은 `gpt-6-luna`의 구조화된 JSON 출력과 중간 수준 추론을, 음성은 `tts-1`의 MP3 출력을 사용한다. 실제 CSS 기술 글 검증에서 기존 `gpt-4.1-mini`는 코드상 대상 요소를 기준 요소로 잘못 읽었다. `gpt-5.4-mini`도 재실행 시 같은 오류가 발생했지만, `gpt-6-luna`의 검증 결과는 코드의 대상 요소와 동작 조건을 올바르게 구분했다. 요약 비용 계산에는 Luna의 입력·캐시 기록·캐시 적중·출력 요금을 반영한다. [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna), [TTS-1](https://developers.openai.com/api/docs/models/tts-1)
- 비용 환산에는 `USD_KRW_RATE`를 쓴다. 기본값 1,700원/USD는 예산 예약을 위한 보수적 설정값이며, 실제 환율이 아니다. 운영자는 배포 시 현재 환율보다 낮지 않게 설정한다.
- 한국 시간으로 일일·월별 사용 기간을 계산한다. 생성 시작 전에 최악 비용을 예약하고, 응답에 사용량이 있으면 실제 요약 비용으로 정산한다. 사용량을 확인할 수 없는 실패와 중단된 작업은 예약액을 보수적으로 비용에 남긴다.
- `articles`는 URL별 결과를 공유하고, `generation_jobs`는 성공한 생성 횟수와 비용을 기록한다. PostgreSQL 함수는 단일 상태 행을 잠가 동시 생성·한도 결정을 직렬화한다. 10분 동안 유효한 URL별 작업 임대가 끝나면 다음 요청에서 회수한다.
- Supabase Storage의 `readly-audio` 버킷은 비공개다. 인증과 초대 여부를 확인한 서버 경로만 짧은 유효 기간의 재생 URL을 발급한다.
- OpenAI 프로젝트에는 지출 알림과 함께 **Enforce a hard limit**을 켠 월 한도를 둔다. OpenAI 문서에 따르면 알림만으로는 요청이 멈추지 않으며, 강제 한도의 적용에도 약간의 지연이 있다. 앱의 24,000원 사전 중단과 별개로 설정한다. [OpenAI Spend limits](https://developers.openai.com/api/docs/guides/spend-limits)

## 요약 재생성 구현 선택 (2026-09-23)

[기획 기록의 요약 재생성 결정](./ADR.md#요약-재생성-결정-2026-09-23)을 구현한 방식이다.

- [재생성 마이그레이션](../supabase/migrations/202609230002_regeneration.sql)은 `regeneration_requests`에 글당 대기 요청 한 건을 보관하고, `generation_jobs.regeneration`으로 기존 생성과 재생성을 구분한다. 초기 마이그레이션 다음에 적용해야 한다.
- 서버는 로그인·초대 여부와 방장 이메일 `yoofh2006@gmail.com`을 검사한다. 재생성 시작 함수도 방장 계정을 확인하고, 일반 사용자의 요청 함수는 방장 요청을 거절한다. 두 함수는 서버의 `service_role`에만 실행 권한을 준다.
- 재생성은 저장된 결과를 반환하는 일반 생성 경로와 별도로 시작한다. 기존의 URL별 작업 임대, 방장 계정의 일일 5회 한도, 서비스의 월 24,000원 사전 중단 규칙을 함께 적용한다. 요청만 접수할 때는 생성 작업을 시작하지 않는다.
- 새 요약을 저장하는 트랜잭션에서 대기 요청과 기존 음성 경로를 해제한다. 재생성에 실패하면 기존 요약·음성·요청을 유지한다. 이전 음성 파일은 저장 성공 후 삭제를 시도하며, 파일 삭제 실패는 새 요약을 되돌리지 않는다.
- 홈의 방장 요청 목록과 상단 건수는 30초마다 갱신한다. 일괄 재생성은 요청을 하나씩 처리하며, 일일 한도나 월 예산에 걸리면 남은 요청을 목록에 둔다. 이메일이나 푸시 알림은 구현하지 않았다.

## 초대장 구현 선택 (2026-09-23)

[기획 기록의 초대장 결정](./ADR.md#초대장-결정-2026-09-23)을 구현한 방식이다.

- [초대장 마이그레이션](../supabase/migrations/202609230003_invitations.sql)은 일회용 링크의 해시·만료·사용·취소 상태를 보관한다. 원본 토큰은 발급 응답에만 제공하며 데이터베이스에는 저장하지 않는다.
- 방장 인증을 서버와 발급·취소 함수 양쪽에서 확인한다. 링크 수락 함수는 행 잠금으로 선착순 한 계정만 화이트리스트에 등록하고 사용 처리한다. 사용 실패나 이미 초대된 계정의 로그인에는 링크를 소모하지 않는다.
- 초대장 페이지는 Three.js 메시·조명·카메라로 봉투가 열리는 장면을 그린다. WebGL을 사용할 수 없는 경우에도 편지 문구와 로그인 버튼은 사용할 수 있다.
- 초대 전용 OAuth 콜백을 사용한다. 짧은 수명의 HttpOnly 쿠키로 토큰을 콜백에 전달해 외부 OAuth 리디렉션 URL에 원본 링크 토큰을 넣지 않는다. Supabase Auth에 `/auth/invite-callback`을 추가 등록해야 한다.
