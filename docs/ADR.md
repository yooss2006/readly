# Readly 기획 기록

## 확정된 방향

- 프로젝트 이름은 Readly다.
- Readly는 인터넷의 URL 글에 대한 요약을 보거나 음성으로 들을 수 있는 웹 서비스다.
- 처음 시작할 때 대상으로 삼는 글은 URL로 볼 수 있는 인터넷의 정보성 글 전반이다.
- 첫 MVP에서는 로그인 없이 열리는 정보성 글만 다룬다.
- 첫 MVP의 입력은 일반 웹 글로 한정하며 PDF URL은 포함하지 않는다.
- 음성으로 듣는 내용은 요약본만 제공한다.
- 요약본과 해당 음성은 한국어로 제공한다.
- 처음에는 본인이 사용할 MVP로 만들고, 주변 사람들에게 사용해 보게 하면서 개선할 예정이다.
- 첫 MVP는 본인과 초대한 주변 사람만 사용할 수 있다.
- 첫 MVP에서는 초대받은 사람마다 개별 계정을 둔다.
- 첫 MVP에서는 계정마다 새 결과를 만드는 작업을 하루 최대 5회로 제한한다.
- 새 요약 생성, 요약과 음성 동시 생성, 기존 요약에 음성 추가는 각각 1회로 센다. 보관된 결과를 다시 보는 것은 횟수에 포함하지 않는다.
- 생성에 성공한 작업만 일일 횟수에서 차감한다. 요약은 성공했지만 음성이 실패하면 요약을 보관하고, 음성은 나중에 다시 시도할 수 있다.
- 요약과 음성을 함께 요청했을 때 요약만 성공하면 요약 생성 1회만 차감한다. 이후 음성 추가에 성공하면 1회를 더 차감한다.
- 새 요청에 따라 늘어나는 본문 추출·요약·음성 생성 비용에 월 3만 원의 서비스 전체 지출 상한을 둔다.
- 서비스 전체 지출 상한에 도달하면 새 요약·음성 생성은 중단하고, 보관된 결과는 계속 이용할 수 있다.
- MVP에서 가장 먼저 확인할 핵심 경험은 글을 읽기 전에 요약을 보는 것이다.
- 요약본 음성 듣기도 첫 MVP에 포함한다.
- 첫 MVP에서는 만든 요약을 나중에 다시 읽고, 생성된 음성을 다시 들을 수 있도록 보관한다.
- 사용자는 「요약 생성」과 「요약 + 음성 생성」 중 선택할 수 있다.
- 같은 URL의 보관된 결과는 모든 사용자가 함께 이용한다. 나중에 같은 URL을 다시 입력하면 이전 요약을 그대로 반환한다.
- 같은 URL에 요약만 보관되어 있을 때 「요약 + 음성 생성」을 선택하면 기존 요약은 유지하고 음성만 추가한다.
- 이번 기획에서는 완전히 구체적인 내용보다 큰 방향을 먼저 정한다.

## 요약 재생성 결정 (2026-09-23)

- 초대된 일반 사용자는 저장된 요약의 재생성을 요청할 수 있다. 요청 자체는 생성 횟수와 월 비용을 사용하지 않는다.
- 같은 글에 대한 대기 요청은 한 건으로 모은다. 일반 사용자는 해당 글의 요청 대기 상태를 볼 수 있다.
- 방장 계정 `yoofh2006@gmail.com`에는 요청 버튼 대신 바로 재생성 버튼을 제공한다. 방장은 홈의 요청 목록에서 글을 확인하고 단건 또는 일괄 재생성할 수 있다.
- 방장에게 새 요청은 앱 안의 요청 목록과 대기 건수로 알린다. 이메일 알림은 이 결정에 포함하지 않는다.
- 재생성한 요약은 같은 URL을 이용하는 모든 사용자에게 적용한다. 성공한 재생성은 방장 계정의 일일 생성 횟수와 서비스의 월 비용 한도에 포함한다.
- 재생성에 성공하면 대기 요청을 해소하고 이전 요약의 음성을 해제한다. 실패하면 요청과 기존 요약·음성을 유지한다. 새 요약의 음성은 이후 다시 생성할 수 있다.

구현 방식은 [요약 재생성 기술 결정](./TECHNICAL_DECISIONS.md#요약-재생성-구현-선택-2026-09-23)에 기록한다.

## 초대장 결정 (2026-09-23)

- 방장은 이메일을 미리 지정하는 대신 일회용 초대 링크를 만들어 공유한다. 링크를 가진 첫 번째 사람이 Google 로그인에 성공하면 일반 사용자로 등록되고 메인 화면으로 이동한다.
- 초대 링크는 7일 뒤 만료되며 성공적으로 사용한 뒤에는 다시 사용할 수 없다. 사용 전에는 방장이 발급 내역에서 취소할 수 있다.
- 받은 사람에게는 영화 같은 분위기의 입체적인 편지 화면을 보여주고, 편지를 열면 Readly 소개와 Google 로그인으로 이어진다.
- 초대로 가입한 일반 사용자는 기존과 같이 요약·음성을 생성하고 재생성을 요청할 수 있다. 방장 전용 재생성·초대장 관리 권한은 얻지 않는다.

구현 방식은 [초대장 기술 결정](./TECHNICAL_DECISIONS.md#초대장-구현-선택-2026-09-23)에 기록한다.

## 기획 배경: 사용자 진술

- 사용자는 유튜브 영상에 대해 질문하는 기능에서 「요약해줘」를 자주 사용해 요약본을 본다.
- 사용자는 그 요약 내용이 꽤 정확하다고 느낀다.
- 이 경험을 계기로 블로그 글 버전의 서비스를 만들고 싶어졌다.

## 원하는 이용 상황: 사용자 진술

- 본문을 읽기 전에 요약을 먼저 보고 내용을 예습하고 싶다.
- 긴 본문을 읽을 필요가 없다고 판단되는 경우에는 요약만 보고 싶다.
- 지하철 등 이동 중에는 글의 요약본을 음성으로 듣고 싶다.
